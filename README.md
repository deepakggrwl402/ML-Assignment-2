# Credit Risk Classification — ML Assignment 2

BITS WILP — M.Tech (AIML), Machine Learning, Assignment 2

## a. Problem Statement

Banks and lending institutions need to decide whether an applicant is likely to
repay a loan ("good" credit risk) or default ("bad" credit risk) before
approving credit. This project builds and compares five supervised
classification models that predict an applicant's credit risk from their
financial and demographic attributes, and exposes them through an interactive
Streamlit web app so evaluators can upload test data and inspect model
performance without retraining.

## b. Dataset Description

- **Name:** German Credit Risk (Statlog German Credit Data)
- **Source:** UCI Machine Learning Repository, accessed via OpenML (`credit-g`, version 1)
- **Instances:** 1,000
- **Features:** 20 (7 numeric, 13 categorical) — e.g. checking account status,
  credit duration, credit history, purpose, credit amount, savings status,
  employment duration, installment rate, personal status, age, housing,
  existing credits, job, and foreign worker status.
- **Target:** `class` — binary, `good` (700 instances) vs `bad` (300 instances)
- **Split used for experiments:** 80% train (800 rows) / 20% test (200 rows),
  stratified on the target. The 200-row test split is shipped as
  [`test_data.csv`](./test_data.csv) and is what the Streamlit app expects to
  be uploaded.

## d. Models Used

All five models are trained on the same dataset and the same train/test split,
using a shared preprocessing pipeline (`StandardScaler` for numeric features,
`OneHotEncoder` for categorical features) wrapped together with each
classifier in a single `sklearn.pipeline.Pipeline`, so the saved model files
can be applied directly to raw test data.

1. Logistic Regression
2. Decision Tree Classifier
3. K-Nearest Neighbor Classifier
4. Naive Bayes Classifier (Gaussian)
5. Support Vector Machine (RBF kernel)

### Comparison Table (evaluated on the 200-row held-out test split)

| ML Model Name | Accuracy | AUC | Precision | Recall | F1 | MCC |
|---|---|---|---|---|---|---|
| Logistic Regression | 0.7050 | 0.7594 | 0.7755 | 0.8143 | 0.7944 | 0.2744 |
| Decision Tree | 0.6950 | 0.7083 | 0.8264 | 0.7143 | 0.7663 | 0.3415 |
| KNN | 0.7250 | 0.7117 | 0.7429 | 0.9286 | 0.8254 | 0.2474 |
| Naive Bayes | 0.6800 | 0.7109 | 0.8333 | 0.6786 | 0.7480 | 0.3350 |
| Support Vector Machine | 0.7400 | 0.7835 | 0.7716 | 0.8929 | 0.8278 | 0.3226 |

*(Exact values are regenerated by `train_models.py` and saved to
`model/metrics.csv`; reproduce with `python train_models.py`.)*

### Observations

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Strong, well-balanced baseline with the second-highest AUC (0.7594), indicating the classes are fairly linearly separable after one-hot encoding. Precision and recall are both reasonable, but MCC (0.2744) is the lowest among all models, meaning it struggles more than others to correctly separate the minority "bad" class. |
| Decision Tree | Highest precision (0.8264) but lower recall (0.7143) — it is conservative about predicting "good", making fewer false-good predictions but missing some good applicants. Its MCC (0.3415) is the best of all five, suggesting the best overall balance between the two classes despite a middling accuracy. |
| KNN | Highest recall (0.9286) and second-highest F1 (0.8254), but the lowest MCC (0.2474) — it is biased toward predicting the majority "good" class, inflating recall/F1 while doing poorly at identifying "bad" applicants. Sensitive to feature scaling, which was addressed via `StandardScaler`. |
| Naive Bayes | Lowest accuracy (0.6800) and recall (0.6786), reflecting its restrictive conditional-independence and Gaussian-distribution assumptions, which fit this mixed categorical/numeric credit data poorly. Still achieves the second-highest MCC (0.3350) and precision (0.8333), so its positive predictions are reliable even though it misses many good applicants. |
| Support Vector Machine | Best overall performer: highest accuracy (0.7400), AUC (0.7835), and F1 (0.8278), with strong recall (0.8929). The RBF kernel captures non-linear interactions between features that linear models miss, at the cost of higher training/inference time than the simpler models. |
| **Overall, Winner for your dataset?** | **Support Vector Machine** — it leads on Accuracy, AUC, and F1, and is a close second on MCC, making it the most reliable model overall for this dataset. |

## Streamlit App Features

The app (`app.py`) provides:
- **Dataset upload (CSV):** upload the test split (`test_data.csv`) or any
  compatible CSV containing the original feature columns and the `class`
  target column.
- **Model selection dropdown:** choose any of the five trained models.
- **Evaluation metrics display:** Accuracy, AUC, Precision, Recall, F1, and
  MCC computed live on the uploaded data.
- **Confusion matrix & classification report:** visual confusion matrix plus
  a per-class precision/recall/F1 breakdown.
- **Compare-all-models mode:** optionally run all five models on the uploaded
  data and view a side-by-side comparison table and bar chart.

Models are loaded directly from the saved `.joblib` pipelines — **no
retraining occurs when the app runs**; it only performs inference and metric
computation on the uploaded data.
